## Change type

**Feature / Architecture**

## Why this version/state was updated

The previous memory system relied on the legacy `SettingsManager.settings.memories` dictionary stored in `settings.json`. The Brain Core phase created the durable local-first foundation needed for structured JARVIS memory while preserving existing user data and rollback safety.

## What changed

- SQLite became the canonical runtime Brain store.
- Added `BrainService` as the high-level runtime facade.
- Added structured models for memories, entities, people, aliases, facts, relations, provenance, learning events and biometric references.
- Added explicit schema/migrations and exactly-once import of legacy `settings.json` memories.
- Preserved the legacy dictionary as rollback/migration safety rather than deleting it.
- Migrated `MemoryTool` to the canonical Brain runtime path.
- Migrated Memories UI/view-model behavior to observe the canonical Brain store.
- Added startup initialization with failure isolation so Brain failure does not crash unrelated JARVIS functionality.
- Added privacy-safe Brain diagnostics that do not log memory/fact contents.

## What works in this baseline

The Brain Core baseline is verified to provide:

- local SQLite persistence;
- app restart persistence for Brain memories;
- legacy memory import exactly once;
- explicit remember/search/list/forget behavior through the memory tool;
- Memories UI backed by canonical Brain state;
- structured person/fact/relation persistence APIs for future phases;
- safe startup when Brain initializes successfully;
- controlled degradation when Brain initialization fails;
- existing non-Brain JARVIS functionality preserved by regression/smoke validation.

## Known limitations / intentionally not included

This baseline does **not** yet implement:

- automatic learning from normal conversation;
- Retrieval / PromptContextBuilder for normal conversational context;
- embeddings or vector search;
- memory reinforcement/decay;
- Obsidian runtime projection/sync;
- cloud Brain sync;
- model-weight training.

Gemini/OpenAI/OpenClaw may therefore still have different contextual-memory behavior until the Retrieval + PromptContextBuilder phase is complete.
